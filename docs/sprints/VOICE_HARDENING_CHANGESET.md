# JARVIS Voice/TTS Hardening changeset

Date: 2026-08-17

## Root cause evidence

The pre-change runtime probe for `Error 455` returned:

```json
{
  "unsafe_before": false,
  "sanitized_before": "Error 455",
  "selected_provider": "piper",
  "selected_voice": "jarvis-medium",
  "selected_language": "en"
}
```

`config/settings.json` selected `data/models/piper/jarvis-medium.onnx`.
`PiperTTS._select_voice` inferred language from Cyrillic presence, so a raw
ASCII error selected the local English voice. Runtime logs independently show
Piper loading `jarvis-medium` and `ru_RU-dmitri-medium`. Production frontend
sources contain no browser `SpeechSynthesis`; Windows `winsound` only played
the WAV generated by Piper.

## After pipeline

```text
AgentOutcome
  -> AssistantOutput(display/speech/debug/error)
  -> SpeechRenderer
  -> defense-in-depth sanitizer
  -> TTSQueue(RenderedSpeech)
  -> local Russian Piper
  -> WAV/audio
```

## Fallback policy

Primary provider is local Piper, language `ru`, voice
`ru_RU-dmitri-medium`, configured fallback `none`. An incompatible English
voice is never selected. A TTS failure leaves `display_text` available and
produces no speech.
